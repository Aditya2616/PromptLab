Read this before trusting a number

  • Much of the gain is output-format control. A 0.5B model often knows the answer but replies in a shape the scorer rejects. Telling it to reply with only the answer is worth many points; that is a real effect, but it is not reasoning.
  • Dev sets are small and noisy. A few dozen items means a standard error of several points, so some "improvements" during search are luck. That is why the winner is re-scored on a separate test split.
  • The test split is touched once, after the search is finished. Dev minus test accuracy of the winner is the winner's-curse gap.
  • Random search at equal budget is the fair baseline. If evolution does not beat it, selection is not adding anything.
  • One seed per task, one small model. Confidence intervals are shown; a result that is not significant is reported as it is.
